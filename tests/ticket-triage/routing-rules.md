# NovaDesk Ticket Routing Rules

## Purpose

These rules define how incoming NovaDesk support tickets should be categorized and routed.

## Categories

### Account & Access
Use when the issue involves:
- Login problems affecting an individual user
- Password or authentication issues
- Account access problems limited to a specific user or account

Default Route:
Support / Account Team

### Billing
Use when the issue involves:
- Charges
- Invoices
- Refunds
- Credits
- Subscription billing

Default Route:
Billing Team

### Product Usage
Use when:
- A feature is difficult to use
- A user needs help understanding product functionality
- A feature is behaving unexpectedly for an individual customer

Default Route:
Product Support Team

### Service Outage
Use when:
- NovaDesk itself appears unavailable
- Multiple users or teams are unable to access the service
- Customers report widespread errors
- The same service failure affects users across multiple locations
- Errors indicate a possible platform-wide availability problem

Default Route:
Engineering / Incident Response

### Security
Use when:
- There is a suspected security incident
- Unauthorized access is reported
- Credentials or sensitive account information may have been compromised
- A customer reports suspicious activity that may represent a security issue

Default Route:
Security Team

### Legal
Use when:
- The ticket contains a legal threat
- The customer requests legal documentation
- There is a formal legal or regulatory concern

Default Route:
Legal Team

## Priority Levels

### Critical
Use when:
- A widespread service outage is affecting multiple users or customers
- A security incident may be occurring
- A major platform function is unavailable to a significant number of users

### High
Use when:
- A significant customer-facing issue is affecting an important workflow
- The issue has substantial business impact but does not meet Critical criteria

### Medium
Use for normal product, billing, or account issues that have meaningful but limited impact.

### Low
Use for informational requests, minor issues, or requests without significant operational impact.
